PROMPT V'GINE — PRODUCT KNOWLEDGE FOUNDATION V1 — AUTHORING REQUEST
==================================================================

PURPOSE
Replace the current generated/meta Product Knowledge copy with a real user-facing music-production dictionary.
The explanations must teach what each musical term, value, phrase, production characteristic, or undesirable condition actually means.
Do NOT explain how the UI works and do NOT describe an item as a preset, option, control, or prompt fragment.

AUTHORING RULES
1. Write one concise expert explanation in English and one natural German equivalent for every entry below.
2. EN and DE should each be one short paragraph, normally 25–70 words. Prefer clarity over hitting a word count.
3. Start with what the term/phrase IS. Then explain what it sounds/feels like or what it changes in music/production when useful.
4. Never use meta copy such as: 'this preset', 'this option', 'this control', 'sets X to', 'renders as', 'adds to Exclude', 'packages a musical direction', 'Product Editor', or prompt-syntax explanations.
5. Do not merely restate the label. Define jargon in plain language and avoid circular definitions.
6. Historical/era entries: describe broad period-typical recording, arrangement, instrumentation, media, dynamics, stereo, effects, and mix tendencies where relevant. Treat them as tendencies, not rules; do not imply every record from a decade sounds the same.
7. BPM entries: explain the tempo feel/range meaning. Mention half-time/double-time perception only where useful; do not equate BPM mechanically with emotional intensity.
8. Key/mode entries: explain the tonal structure or modal character. Avoid simplistic claims such as 'major = happy' or 'minor = sad' as universal rules.
9. Groove/rhythm entries: explain timing, subdivision, accent placement, pocket, swing, syncopation, or feel in audible terms.
10. Production/mix entries: use accurate engineering language, but make it understandable. Distinguish cause from audible result when they are not one-to-one.
11. Sonic adjectives and compound phrases: unpack the meaningful components and explain the combined audible result.
12. Easy statements: explain the WHOLE phrase as a musical direction; do not call it a preset. If it combines several concepts, briefly unpack them.
13. Exclude entries: define the undesirable sonic/arrangement condition itself and why it can be problematic when excessive; do not explain that the UI excludes it.
14. Avoid artist names, song titles, brand/equipment endorsements, marketing language, and fake precision.
15. If a term is context-dependent or ambiguous, say so briefly rather than inventing certainty.
16. Preserve the exact ID. Do not invent, merge, split, rename, or omit entries.

RETURN FORMAT — STRICT
Return plain UTF-8 text only. No Markdown table, no commentary before/after, no code fence.
Return all entries in the same order using exactly this 4-line block:

ID: <exact id>
EN: <single-paragraph English explanation>
DE: <single-paragraph German explanation>
